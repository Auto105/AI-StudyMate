# AI StudyMate POC PRD

## 1. Executive Summary

AI StudyMate는 강의 전사 텍스트와 PDF 자료를 기반으로 AI 요약, 자료 기반 Q&A, 문제 생성, 그리고 시험일까지의 학습 계획을 제공하는 대학생용 학습 도우미입니다.

이번 POC의 핵심은 단순한 AI 채팅이 아니라, 자료 분석 결과를 **오늘의 학습 행동**으로 연결하는 것입니다.

---

## 2. Background

대학생은 강의자료, 개인 필기, 시험일을 여러 도구에 나누어 관리합니다.

다음과 같은 불편이 반복됩니다.

- 긴 강의자료에서 핵심 내용을 찾는 데 시간이 오래 걸립니다.
- 전사 텍스트와 PDF 자료를 함께 복습하기 어렵습니다.
- 시험일까지 남은 기간에 맞는 공부 계획을 매번 직접 세워야 합니다.
- 일반 AI 챗봇은 사용자가 먼저 질문해야 하며, 다음 행동을 제안하지 않습니다.

---

## 3. Problem Statement

> 학생은 학습자료를 가지고 있어도, 무엇을 먼저 이해하고 오늘 무엇을 공부해야 하는지 결정하기 어렵습니다.

AI StudyMate는 이 문제를 다음 세 단계로 해결합니다.

1. 자료를 통합합니다.
2. AI가 핵심 내용을 정리합니다.
3. 시험일까지의 학습 행동으로 변환합니다.

---

## 4. Target Users

### Primary User

- 대학 강의를 수강하는 학부생
- 시험 대비를 위해 강의자료를 빠르게 정리해야 하는 학생
- 녹음 전사 텍스트와 PDF 자료를 함께 복습하는 학생

### User Needs

- 긴 자료의 핵심을 빠르게 파악하고 싶습니다.
- 자료 범위 안에서 질문하고 싶습니다.
- 핵심 개념을 문제로 확인하고 싶습니다.
- 시험일까지 무엇을 공부할지 알고 싶습니다.

---

## 5. Product Goal

### Primary Goal

텍스트와 PDF 자료를 AI가 분석하여 요약, Q&A, 문제 생성, Today Plan까지 하나의 학습 흐름으로 제공합니다.

### Secondary Goal

사용자가 앱을 다시 열어도 과목, 시험일, 자료, 요약 상태가 유지되도록 합니다.

---

## 6. Success Criteria

POC 성공 기준은 다음과 같습니다.

- 텍스트 또는 PDF를 정상 입력할 수 있습니다.
- PDF에서 텍스트를 추출할 수 있습니다.
- 입력 자료를 바탕으로 요약을 생성할 수 있습니다.
- 자료 범위 안의 질문에 답할 수 있습니다.
- 문제를 생성할 수 있습니다.
- 시험일에 따라 Today Plan이 달라집니다.
- 새로고침 후 핵심 상태가 유지됩니다.
- 발표 시 핵심 흐름을 오류 없이 재현할 수 있습니다.

## 8. Functional Requirements

### 8.1 Today

- 앱의 기본 진입 화면입니다.
- 과목명과 시험일을 표시하고 저장합니다.
- D-Day를 계산합니다.
- 시험일까지 남은 기간에 따라 Today Task를 제공합니다.
- 시험일 변경 시 계획이 달라져야 합니다.

### 8.2 Materials

- 전사 텍스트를 붙여넣을 수 있습니다.
- PDF 파일을 업로드할 수 있습니다.
- PDF 파일은 5MB 이하만 허용합니다.
- 추출 텍스트는 최대 12,000자까지 사용합니다.
- 추출 결과를 화면과 localStorage에 반영합니다.

### 8.3 Summary

- 입력 자료의 핵심 키워드를 생성합니다.
- 핵심 개념을 정리합니다.
- 쉬운 설명을 제공합니다.
- 실제 summary 상태를 화면에 렌더링합니다.

### 8.4 Questions

- 입력 자료와 질문을 함께 API에 전달합니다.
- 자료 안 질문에는 근거 있는 답변을 제공합니다.
- 자료 밖 질문에는 `"자료에 없습니다."` 의미의 응답을 제공합니다.

### 8.5 Quiz

- 객관식 문제를 생성합니다.
- OX 문제를 생성합니다.
- 정답과 설명을 제공합니다.
- POC에서 우선순위는 Summary, Q&A, Today Plan 다음입니다.

### 8.6 Plan

- 과목명, 시험일, 키워드, 개념을 입력으로 사용합니다.
- D-Day에 따라 계획 길이와 우선순위를 조절합니다.
- D-5와 D-2에서 서로 다른 계획을 제공합니다.

## 10. Runtime Strategy

### Mock Mode

```env
USE_MOCK_API=true
```

- 발표 전 기본 안정화와 개발 검증에 사용합니다.
- 실제 OpenAI 요청이 발생하지 않습니다.
- 자료에 맞는 일관된 Mock 응답을 제공해야 합니다.

### OpenAI Mode

```env
USE_MOCK_API=false
OPENAI_API_KEY=...
```

- 발표 시 실제 AI 적용 범위에 사용합니다.
- API 키는 서버 Route Handler에서만 사용합니다.
- 실제 지원 Route 상태는 API Contract를 따릅니다.

## 12. UX Principles

- 사용자가 첫 화면에서 오늘 할 일을 바로 이해할 수 있어야 합니다.
- 데이터가 없는 경우 명확한 Empty State를 제공합니다.
- API 요청 중에는 Loading 상태를 표시합니다.
- 오류 발생 시 사용자가 이해할 수 있는 메시지를 제공합니다.
- 하드코딩 예시 데이터와 실제 사용자 데이터를 혼동하지 않도록 합니다.

---

## 13. Non-Functional Requirements

- TypeScript 오류가 없어야 합니다.
- `npm run build`가 성공해야 합니다.
- 모든 API 실패 응답은 JSON이어야 합니다.
- API 키는 클라이언트에 노출되면 안 됩니다.
- UI 컴포넌트는 localStorage를 직접 호출하지 않습니다.
- API 호출은 공통 client를 사용합니다.
- 발표용 PDF로 실제 성공 흐름을 검증해야 합니다.

## 15. Risks and Mitigation

| 위험 | 대응 |
| --- | --- |
| OpenAI 응답 지연 또는 오류 | Mock fallback 준비 |
| PDF 파싱 실패 | 텍스트 붙여넣기 fallback 제공 |
| API 응답과 UI 타입 불일치 | API Contract 및 TypeScript 타입 유지 |
| 발표 직전 기능 변경 | 기능 동결 후 버그 수정만 허용 |
| 하드코딩 데이터 노출 | 실제 상태 렌더링 및 데모 데이터 검증 |
